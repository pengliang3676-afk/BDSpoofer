【真因】
  bds_shouldBlockPasteboardRead 挂在 UIPasteboard 的 string / strings / URL / items
  四个 getter 上，可被任意线程调用。9.30-20 在其中加入：

      static CFAbsoluteTime activeSince = 0;
      static dispatch_once_t once;
      dispatch_once(&once, ^{
          activeSince = CFAbsoluteTimeGetCurrent();
          [NSNotificationCenter.defaultCenter addObserverForName:...
                                                         queue:NSOperationQueue.mainQueue
                                                    usingBlock:^(NSNotification *n) { ... }];
      });

  dispatch_once 首次执行落在哪个线程，就会从那个线程去操作 NSNotificationCenter
  的内部表。后台线程注册 / 主线程使用 -> 竞态 -> 内部表被写坏 ->
  对象指针损坏 -> 后台队列打日志时 objc_msgSend 崩溃。
  与崩溃线程恰为后台队列、崩溃点为 NSLog 格式化对象完全吻合。

【本版改动】
  bds_shouldBlockPasteboardRead 移除该通知观察者注册，恢复 9.30-19 的行为：
  非活动状态一律拦，活动状态放行。失去的仅是"回到前台若干秒内也拦"这一
  9.30-20 自行追加、非需求项的行为。

  同时保留 9.30-25 的三项修复（sysctl 纯透传 / task_info 与 host_statistics64
  判空 / getsockname 判空）与 9.30-24 的内网 IP 池调整。
