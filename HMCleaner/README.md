# 河马清理 0.1.0

独立 App，Bundle ID `com.codex.hmcleaner`。目标固定为河马剧场 `com.cbn.hmjc`，不修改卍解、卐解或 HMProbe4。面向 iOS 15 及以上的 RootHide 越狱环境，依赖设备已安装 Crane 完整版；此包不是注入到河马的 dylib，也不是通用 IPA。

## 当前范围

这一版完成**文件清理、备份、恢复缺失文件、前后对比**。**钥匙串清理未启用**：现有日志没有证实实际访问组与每个容器的对应关系，部分 service/account 已脱敏；界面明确列为待核实。本版没有调用 SecItemDelete，也不读取全局钥匙串。待设备提供确切映射后才能加入精确规则、加密备份和相应验证。

仅允许所选容器的 Documents 下以下 5 个具体文件，不接受自定义路径、通配符或递归删除：

- `.PID4SM.txt`
- `FP_SEQ.txt`
- `come2`
- `PdnuLKiM`
- `.thumbcache_ED91762CA5ED7B556B28BA051E9F978D`

它们来自用户提供的 HMProbe4 日志的文件记录。界面分组方便核对，不把文件名、主二进制或附近堆栈地址当作 SDK 归属证明。此后不同版本/容器生成的其他名字不会自动匹配。

## 使用

1. 安装 `HMCleaner_0.1.0_RootHide.deb`，从桌面打开“河马清理”。
2. 选择容器，核对名称、ID、Crane 返回的真实主目录和文件清单。扫描默认不勾选，不创建目标文件。
3. 从多任务界面划掉河马剧场，勾选需要清理的文件，点“备份并清理勾选项”，在确认框核对具体清单。执行期间不要启动河马、切换容器或使用其他工具修改这些文件。
4. 查看逐项结果。可以冷启动河马后返回“备份 → 重新验证”，比较文件是否重新出现、内容是否与备份相同；此比较不证明 SDK 归属或服务器状态。
5. 若要恢复，先退出河马，点“恢复缺失文件”。已重新生成的文件会跳过，不覆盖。恢复内容、所有者和基本权限，不恢复时间戳、ACL、扩展属性，也不等于整个容器回滚。

备份位于 `/var/mobile/Library/Application Support/HMCleaner/Backups/<UUID>`，不在河马容器里。目录权限 0700、文件权限 0600，按操作独立保存，卸载工具也不会自动删除。文件内容可能含本机标识；本版不上传备份、不生成对外请求。备份是本机文件备份，**没有额外口令加密**。导出按钮仅分享结果文字，不含原文件内容。

## 执行保护和限制

- 通过 libCrane 的类型化枚举获得主应用/共享/扩展目录；共享和扩展目录仅显示。主目录必须位于系统注册的目标应用数据目录内且在容器间唯一；无法确认时禁用操作，不猜测路径。
- 每次清理/恢复前重新核对容器 ID、路径、设备号和 inode。容器被删除或路径改变会停止，绝不自动新建原容器。
- 用进程列表检查主 App 和内置扩展；检查失败或进程仍在运行就拒绝执行。检查与文件操作不是系统级锁，仍须遵守执行期间不重新启动/切换的要求。
- 文件和路径组件不跟随符号链接；只接受单硬链接的普通文件，单项最多 1 MiB。扫描后内容或元数据变化会停止该项。
- 先把全部选中项备份、读回校验 SHA-256 并持久化清单，再清理。原文件先以排他重命名暂时移开、复查身份与内容，再删除；不使用目录递归清空。
- 中途退出可能留下不完整记录或 `.hmcleaner-*.pending` 临时项，不能将其当作成功。备份记录会提示重新验证；这些临时项不会按通配符自动删除。
- 本版不自动更换 IP、创建/切换容器、修改设备标识或伪造网络请求，也不承诺清除服务端历史。
- HMProbe4 现有网络日志来自请求任务创建入口，不等于已发送成功或第三方已收到。

## 构建与测试

在带 iPhoneOS SDK 的 macOS 上运行 `bash HMCleaner/build.sh`。脚本先执行 macOS 临时目录中的真实文件操作测试，再编译 iOS 15 起的 arm64 + arm64e App、签名、验证并封装 RootHide deb。不会连接或清理手机。

测试覆盖：备份/清理/恢复、同名文件不覆盖、相同长度内容变化、路径穿越、文件/父目录符号链接、硬链接、FIFO、超限文件、扫描不写入、运行中拒绝、取消、容器身份变化、备份内容损坏、非法备份 ID。模拟环境测试不证明真实设备上的 Crane 权限、路径或进程接口兼容。

接口依据：[Crane 作者公开头文件](https://github.com/opa334/Crane-Resources/blob/master/libCrane/libCrane.h)、[libCrane 使用说明](https://github.com/opa334/Crane-Resources)。没有引用私有实现来猜测 Keychain 访问组。
